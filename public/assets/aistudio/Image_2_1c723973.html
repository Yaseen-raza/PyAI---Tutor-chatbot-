Can you explain why using a list comprehension is better than a regular for loop with .append()? And when should I switch to a generator expression instead?

Great question! While both yield the identical result, Python handles them fundamentally differently under the hood across three major axes: readability, C-level bytecode speed, and allocation ergonomics.

speed Bytecode Speed

Avoids overhead of repeated LIST_APPEND function calls and attribute lookups in Python's VM.

visibility High Readability

Declares what the list contains declaratively in one readable pass rather than imperative state mutations.

memory Generator Shift

Switch to generator expressions (...) when data streams exceed RAM or when iterating only once.

comprehensions_comparison.py 
# Example: Squaring even numbers
# Method 1: Traditional Loop
even_squares = []
for num in range(10):
    if num % 2 == 0:
        even_squares.append(num ** 2)

# Method 2: Pythonic List Comprehension (Faster, cleaner)
even_squares = [num ** 2 for num in range(10) if num % 2 == 0]
print(even_squares)  # Output: [0, 4, 16, 36, 64]
num ** 2 Expression: What gets evaluated and added to the resulting collection.
for num in range(10) Iteration: The sequence or iterable generator driving the loop.
if num % 2 == 0 Predicate Filter: Optional conditional filter executed before expression evaluation.
analytics Memory Analysis: List vs Generator Evaluation 99.9% Memory Reduction

Lists instantiate and hold all values in RAM at once (O(N) memory footprint). A Generator Expression uses lazy iteration via the iterator protocol (O(1) space).

List [x for x in 1M]: ~9.0 MB Generator (x for x in 1M): 104 Bytes
Full RAM Consumption (List) Constant Footprint (Generator)

# 2. Inspect raw byte size in CPython heap
list_size = sys.getsizeof(list_comp)
gen_size = sys.getsizeof(gen_exp)
